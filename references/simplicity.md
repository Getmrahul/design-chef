# Make the next action easy

Use this reference when a screen feels overwhelming or the task is simple but the interface is crowded. Optimize for the user's total effort: reading, decisions, clicks, memory, and recovery.

## Decide what belongs on the screen

For each element, choose one:

| Treatment | When it fits |
| --- | --- |
| Keep visible | Needed to understand the task, decide, act, or recover now. |
| Reveal on request | Useful optional detail or an infrequent setting that users can discover through a clear label. |
| Show in a later step | Depends on an earlier answer, needs substantial attention, or is irrelevant until the task progresses. |
| Remove | Repeats information, decorates without purpose, or supports an unrelated task. |

Do not use hidden controls to conceal essential information, errors, prices, permissions, or consequential choices. A collapsed section should say what it contains; “Advanced settings” can work for technical options, while “More” often tells the user too little.

## Examples

### Start a focus session

**Overloaded:** a welcome paragraph, streak cards, charts, motivational badges, preset grids, several settings panels, and equally prominent Start, Analyze, Explore, and Upgrade buttons.

**Focused:** a session duration with a useful default, a clear **Start session** button, and a quiet **Session settings** disclosure for sound or notifications. Keep a task-name field only if naming the task helps the workflow. Put history in its own destination if it is a separate job.

The goal is to start a session; an empty area around the timer does not need another card.

### Upload a document

**Overloaded:** introductory prose, feature cards, detailed instructions, output settings, and several upload methods all competing before a file is selected.

**Focused:** **Choose a document**, the file picker or drop zone, and essential file-type or size limits. After selection, show the filename, remove/replace control, and any required next choice. Reveal optional output settings when relevant. Keep upload progress, errors, and retry clear.

If selecting a file immediately sends it, communicate that behavior at the selection point. Do not hide an upload consequence to make the screen look simpler.

### Book an appointment

Use steps when appointment type determines availability, and the chosen slot determines which details are needed. Preserve selections when moving back and provide a review before confirmation.

If the task only asks for a name, email, and an already chosen slot, one short form is usually easier than three screens. Keep related fields together.

### Review an analytics dashboard

A dashboard may legitimately need several metrics, filters, and comparisons at once. Establish a clear overview, group related information, and put detailed investigation behind a drill-down. Preserve side-by-side data needed for comparison.

Do not strip useful context simply to achieve a sparse layout or enforce one action across the entire dashboard.

## A practical review

- Can someone identify the screen's job and next action from its heading and controls?
- Is there a single dominant action for the current focused task?
- Does each visible sentence help a decision or prevent an error?
- Are secondary actions available without competing for attention?
- Can optional content wait without making it hard to find?
- Does splitting the flow reduce effort, or merely add clicks and memory work?
- Do mobile layouts preserve the same priority?
- Can users navigate disclosures, go back, correct errors, and retain their input?

When simplifying an existing screen, explain the few changes with the biggest effect: what was removed, shortened, deferred, or regrouped, and why that makes the task easier.
